# Worker для Windows Server 2003 (Python 3.4.4)

## Вимоги

- Windows Server 2003 SP2 або пізніше
- Python 3.4.4
- 1С:Підприємство 7.7
- RabbitMQ доступен по мережі (не в Docker)

## Інсталяція

Перейдіть в каталог **інформаційної бази 1С 7.7** (наприкдад D:\Bases\Trade77) і створіть каталог `api`.

```cmd
cd D:\Bases\Trade77 
mkdir api
cd api
```

Вміст каталога `windows_2003` з репозиторія скопіюйте каталог `api`, наприклад:

```cmd
xcopy you_git_folder\windows_2003 /e
```

В результаті маєте отримати в каталозі `D:\Bases\Trade77\api` наступну структуру

```text
.
  ├── .env.example
  ├── bridge.vbs
  ├── config.py
  ├── consumer.py
  ├── logs
  │   └── consumer.log
  ├── README_WINDOWS_2003.md
  ├── reports
  │   ├── test.ert
  │   └── json_for_test
  │       └── test.ert
  └── requirements.txt
```

## Конфігурація


Створіть `.env` файл у папці `api` 

```cmd
copy .env.example .env
```

Змініть налаштування.

```env
# RabbitMQ Configuration
RABBITMQ_DEFAULT_USER=user_rabit
RABBITMQ_DEFAULT_PASS=pass_rabit
RABBITMQ_HOST=192.168.1.100
RABBITMQ_PORT=5672
RABBITMQ_QUEUE=events
RABBITMQ_RESULT_QUEUE_PREFIX=results
RABBITMQ_RESULT_TTL_MS=3600000
RABBITMQ_RESULT_QUEUE_EXPIRES_MS=86400000

# 1C Configuration
PATH_1C=D:\Bases\Trade77
USER_1C=user_api
PASS_1C=pass_api
BRIDGE_VBS=D:\Bases\Trade77\api\bridge.vbs
TEMP_DIR=D:\Bases\Trade77\api\logs
CSCRIPT_EXE=C:\WINDOWS\system32\cscript.exe

# Logging
LOG_DIR=D:\Bases\Trade77\api\logs
LOG_FILE=consumer.log
LOG_LEVEL=INFO
LOG_RETENTION_DAYS=5
```

- Замініть `RABBITMQ_HOST` на IP-адресу вашого RabbitMQ сервера.
- Замініть `RABBITMQ_DEFAULT_USER` і `RABBITMQ_DEFAULT_PASS` на дані вашого RabbitMQ сервера.
- Замініть `PATH_1C` на шлях до **інформаційної бази 1С 7.7** (каталог бази для ключа `/D`), а не до папки встановлення програми.
- Замініть `USER_1C` і `PASS_1C` на облікові дані користувача 1С.
- Замініть `BRIDGE_VBS` на шлях до файла `bridge.vbs` (див. нижче).
- `CSCRIPT_EXE` — рекомендовано вказати `C:\Windows\SysWOW64\cscript.exe` на x64, щоб 1С 7.7 COM запускався у 32-bit host.
- `TEMP_DIR` — папка для тимчасових файлів обміну (має існувати).
- `LOG_DIR` — директорія для логів worker.
- `LOG_FILE` — активний файл логів.
- `LOG_LEVEL` — рівень логування (`DEBUG`, `INFO`, `WARNING`, `ERROR`).
- `LOG_RETENTION_DAYS` — скільки календарних днів зберігати логи (за замовчуванням 5).

#### Функция `api_worker`

```1c
Функция api_worker(ПутьФайлаВопрос) Экспорт      
	Перем ЧЧ, ММ, СС;

	Если ПустоеЗначение(ПарсерJSON) = 1 Тогда
		ИнициализацияПарсерJSON(ПарсерJSON);
	КонецЕсли;
	
	ТекущееВремя(ЧЧ, ММ, СС);
	ВремяСтарта = ЧЧ * 3600 + ММ * 60 + СС;
	
	ПутьФайлаОтвет = СтрЗаменить(ПутьФайлаВопрос, ".json", "_out.json");
	
	// Читаем входящий файл
	Попытка
		ФайлJSON = СоздатьОбъект("Текст");
		ТекстJSON = "";
		ФайлJSON.Открыть(ПутьФайлаВопрос);
		Для Номер = 1 По ФайлJSON.КоличествоСтрок() Цикл
			ТекстJSON = ТекстJSON + ФайлJSON.ПолучитьСтроку(Номер);
		КонецЦикла;
		ОбъектJSON = ПарсерJSON.run("parseJSON", ТекстJSON);
		СписокВопрос = Преобразование_JSON_в_СписокЗначений(ОбъектJSON);
	Исключение
		ТекстОшибки = ОписаниеОшибки();
		Перейти ~ВернутьОшибку;
	КонецПопытки;
	
	// Находим внешнюю обработку для выполнения
	ИмяОбработки = СписокВопрос.Получить("procedure");
	Если ПустаяСтрока(ИмяОбработки) = 1 Тогда
		ТекстОшибки = "Key 'procedure' not found";
		Перейти ~ВернутьОшибку;
	КонецЕсли;
	ПутьФайлаОбработки = КаталогИБ() + "api\reports\" + СокрЛП(ИмяОбработки) + ".ert";
	Если ФС.СуществуетФайл(ПутьФайлаОбработки) = 0 Тогда
		ТекстОшибки = "File not found: " + ПутьФайлаОбработки;
		Перейти ~ВернутьОшибку;
	КонецЕсли;

	ЗаписьЖурналаРегистрации(ПутьФайлаОбработки, "Пакетный режим", "Начато выполнение пакетного задания");

	// Задаем Вопрос
	КонтекстФормы = СоздатьОбъект("СписокЗначений");
	КонтекстФормы.ДобавитьЗначение(СписокВопрос, "Вопрос");

	ОткрытьФормуМодально("Отчет", КонтекстФормы, ПутьФайлаОбработки);
	
	// Получаем Ответ
	Ответ = КонтекстФормы.Получить("Ответ");
	Если ТипЗначенияСтр(Ответ) = "СписокЗначений" Тогда
		СписокОтвет = Ответ;   
		Перейти ~ВернутьОтвет;
	Иначе
		ТекстОшибки = "Critical error while executing file: " + ПутьФайлаОбработки;
		
	КонецЕсли;

~ВернутьОшибку:
	СписокОтвет = СоздатьОбъект("СписокЗначений");
	СписокОтвет.ДобавитьЗначение("error", "status");
	СписокОтвет.ДобавитьЗначение(ТекстОшибки, "message");
	
~ВернутьОтвет:

	ЗаписьЖурналаРегистрации(СписокОтвет.Получить("message"), "Пакетный режим", "Завершено выполнение пакетного задания");
	
	ТекущееВремя(ЧЧ, ММ, СС);
	ВремяВыполненияОбработки = ЧЧ * 3600 + ММ * 60 + СС - ВремяСтарта;
	СписокОтвет.ДобавитьЗначение(ВремяВыполненияОбработки, "execution_time_in_seconds");
	
	ФайлJSON = СоздатьОбъект("Текст");
	ФайлJSON.ДобавитьСтроку(Преобразование_СписокЗначений_в_JSON(СписокОтвет));
	ФайлJSON.Записать(ПутьФайлаОтвет);
	
	Возврат ПутьФайлаОтвет;
	
КонецФункции
```

### Бізнес-логіка consumer.py

Worker обробляє запити через VBScript міст до 1С 7.7:

1. **Отримання запиту** від RabbitMQ у форматі JSON (UTF-8)
2. **Створення тимчасового файлу** з payload у кодуванні **Windows-1251**
3. **Запуск VBScript** `bridge.vbs` з параметрами:
   - Шлях до вхідного JSON файлу
   - `PATH_1C` — шлях до 1С
   - `USER_1C` — користувач
   - `PASS_1C` — пароль
4. **Отримання результату** від `bridge.vbs` (шлях до файлу результату у win-1251)
5. **Перекодування результату** з Windows-1251 в UTF-8
6. **Відправка відповіді** через RabbitMQ клієнту

## Технічні особливості

- **Синхронний код** (не asyncio) — сумісний з Python 3.4
- **pika** замість aio-pika — синхронна бібліотека для RabbitMQ
- **Один потік** обробляє повідомлення послідовно (prefetch_count=1)
- **Стійкість до помилок** — при помилці повідомлення повертається в чергу

## Розширення API через обробки 1С

Для створення нових обробок використовуйте `test.ert` як шаблон.
Розглянемо на прикладі отримання прайсу для певної групи товарів.

1. Зробіть копію `test.ert` в `ПолучитьПрайс.ert`

```cmd
cd D:\Bases\Trade77\api\reports
copy test.ert ПолучитьПрайс.ert 
```

2. В конфігураторі внесіть необхідні зміни в оброку `ПолучитьПрайс.ert`:
  - у формі видальть непотрібні змінні і створіть нову зміну `ГрТоваров` = `Справочник.Товари`
  - у функції `Сформировать` зробіть звіт по вибраній групі товарів і результати звіту збережіть в `Списк.Значений` "Ответ"
  - переконайтесь, що обробка виконується без помилок в середовищі 1С і ви бачите на екрані JSON-файл

3. В каталозі `D:\Bases\Trade77\api\reports\json_for_test` створіть файл `ПолучитьПрайс.json`, де `group_number` - номер групи товарі з вашого довідника.

```json
{
    "procedure": "ПолучитьПрайс",
    "parameters": {
        "group_number": 42,
    }
}
```

4. В конфігураторі внесіть необхідні зміни в оброку `ПолучитьПрайс.ert`. 
  - В процедурі `ПриОткрытии()` прочитайте значення з `group_number` заповніть зміну `ГрТоваров` об'єктом з `Справочник.Товари`

5. Перевірте запуск обробки `ПолучитьПрайс.ert` через `bridge.vbs` 

```cmd
C:\WINDOWS\system32\cscript.exe //nologo bridge.vbs D:\Bases\Trade77\api\reports\json_for_test\ПолучитьПрайс.json D:\Bases\Trade77 user_api pass_api
```
6. Перевірте запуск обробки `ПолучитьПрайс.ert` через API з своїм ключем.

```bash
curl -X POST http://localhost:8000/messages/process \
    -H "Content-Type: application/json" \
    -H "X-API-Key: change-me" \
    -d '{
      "procedure": "ПолучитьПрайс",
      "parameters": {
          "group_number": 42,
      }
    }'
```

Якщо ключ не передати або він неправильний, API повертає `401 Unauthorized`.
